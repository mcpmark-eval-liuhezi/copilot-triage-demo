# Triage Playbook

How we triage incoming bug reports in this repository.

## Checklist

- Acknowledge every new bug report within one business day.
- Confirm reproduction steps before assigning severity.
- Label each issue with its area (frontend, backend, api) and a priority.
- Attach logs, screenshots, or stack traces to the issue whenever available.
- Route platform-specific bugs (e.g., Safari) to the owning team.
- Close the loop with the reporter once the fix ships.

## Severity guide

- P1: broken core functionality or a security issue; fix immediately.
- P2: degraded functionality with a workaround; fix within the sprint.
- P3: cosmetic or minor inconvenience; schedule when capacity allows.
